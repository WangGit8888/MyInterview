#### 人力资源库对接

这个功能是对接朗新天霁的人力资源库，核心目标是把他们系统中的人员档案、工作经历、教育经历等数据同步到我们自己的数据库中。

**整体流程是这样的：

朗新那边分配了一个租户ID，我们用这个ID加上固定的账号密码，调用他们的人员列表分页接口。接口支持按 pageSize 和 pageNum 分页，响应中会返回 total 总记录数，我们通过循环分页拉取到所有的人员ID。

拿到这批ID后，我们使用线程池并发调用三个子接口——基本信息接口、工作经历接口、教育经历接口。之所以用线程池，是因为如果串行处理，几万条数据耗时太长，而并发可以显著缩短同步窗口期。

但是，朗新的接口有限流限制：单个接口每分钟最多调用1000次。为了避免触发限流，我们用 Redis + Lua 实现了分布式令牌桶限流器，所有线程在调用前先去令牌桶获取许可。之所以不用 Guava 的 RateLimiter，是因为我们的服务可能多实例部署，Guava 是单机级的，无法在多实例间共享限流状态；而 Redis 方案的限流状态是全局统一的，更利于后续扩展。

整个同步流程通过 XXL-JOB 配置为每天凌晨1点定时触发，避开业务高峰期。

**异常处理方面：

对于接口超时等临时性异常，我们会自动重试最多2次。

对于字段超长、数据格式异常等无法自动恢复的问题，我们会把对应的ID记录到一张 error 表中，并触发告警通知开发人员。同时提供了补偿机制，支持开发人员修复问题后在管理后台手动重跑失败的数据。
