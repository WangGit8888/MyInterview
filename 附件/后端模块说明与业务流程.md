## 一、总体架构

| 项 | 内容 |
|---|---|
| 框架底座 | RuoYi-Vue 前后端分离版（`README.md` 明确说明） |
| Spring Boot | 2.5.12 |
| JDK | 1.8 |
| 持久层 | MyBatis + PageHelper 1.4.1 + Druid 1.2.8 |
| 数据库 | MySQL |
| 缓存 | Redis（Lettuce 连接池，`localhost:6379`） |
| 认证 | JWT（`Authorization` 请求头，默认有效期 30 分钟） |
| 实时推送 | WebSocket（`/websocket/message/{token}`），仅用于站内消息 |
| 定时任务 | Quartz（数据库调度） |
| 报表 | UReport2（`com.bstek.ureport:ureport2-console`） |
| 对象存储 | MinIO（`io.minio`，可选） |
| 接口文档 | Swagger 3（springfox 3.0.0，默认开启） |
| 服务端口 | 8080，context-path `/` |

**代码规模**（不含 `target`）：Java 文件 845 个 / 约 9.36 万行；MyBatis Mapper XML 121 个；数据库表 107 张。

**分层约定**：每个业务对象都是标准的四件套

```
controller/XxxController.java     HTTP 入口，负责参数接收、权限注解、事务边界
domain/Xxx.java                   实体（继承 BaseEntity，带 create_by/create_time 等审计字段）
mapper/XxxMapper.java             接口
resources/mapper/**/XxxMapper.xml SQL（手写 XML，非注解方式）
service/IXxxService.java          业务接口
service/impl/XxxServiceImpl.java  业务实现
```

Controller 普遍继承 `BaseController`（提供 `startPage()` / `getDataTable()` / `toAjax()` / `AjaxResult`）。

## 二、七个 Maven 模块的职责

`ha-mes/pom.xml` 的 `<modules>` 声明了 7 个模块：

| 模块 | 定位 | 关键内容 |
|---|---|---|
| **huaan-admin** | 启动模块 + Web 层 | 主类 `RuoYiApplication`；系统/监控/工具类控制器；**移动端登录、用户、消息接口**；`application.yml` 所在处 |
| **huaan-framework** | 框架核心 | `SecurityConfig`（鉴权白名单）、JWT `TokenService`、WebSocket（`WebSocketServer`/`WebSocketUsers`）、`MessageProvider`、AOP 切面（操作日志/限流/数据源切换）、`MobileLoginService` |
| **huaan-system** | 系统域 | 用户、角色、菜单、部门、岗位、字典、参数、公告、消息、附件、**自动编码规则** |
| **huaan-quartz** | 定时任务 | 任务与日志的增删改查、Cron 调度 |
| **huaan-generator** | 代码生成器 | `gen_table` / `gen_table_column`，按表生成 CRUD |
| **huaan-common** | 公共基础 | `AjaxResult`、`BaseController`、`BaseEntity`、注解、枚举、常量（`UserConstants`）、工具类（Excel/Minio/Http/File） |
| **huaan-mes** | **MES 业务主模块** | 547 个类，子包 `cal / dv / md / pro / qc / report / tm / wm` |

> 阅读建议：先看 `huaan-common` 的 `UserConstants`，它是理解全部单据状态和库存事务的钥匙。

## 四、单据状态机与库存事务类型

全部定义在 `huaan-common/.../constant/UserConstants.java`。

### 4.1 通用单据状态（`ORDER_STATUS_*`）

| 常量 | 值 | 含义 |
|---|---|---|
| `ORDER_STATUS_PREPARE` | `PREPARE` | 草稿（新建单据的默认状态） |
| `ORDER_STATUS_CONFIRMED` | `CONFIRMED` | 已确认 |
| `ORDER_STATUS_APPROVING` | `APPROVING` | 审批中 |
| `ORDER_STATUS_APPROVED` | `APPROVED` | 已审批 |
| `ORDER_STATUS_FINISHED` | `FINISHED` | **已完成（业务上等同"已过账/已执行"）** |

> 关键理解：**"执行"某张单据 = 把状态置为 `FINISHED` 并调用库存引擎**。删除操作通常限制为"只能删除草稿状态"（如 `WmItemRecptController:226`）。

### 4.2 生产任务状态（触控屏端使用）

`NORMAL`（未开始）→ `START`（生产中）⇄ `PAUSE`（暂停）→ `FINISHED`（已完成）

### 4.3 库存事务类型（`TRANSACTION_TYPE_*`）

| 常量值 | 中文含义 |
|---|---|
| `ITEM_RECPT` | 原材料接收入库 |
| `ITEM_RTV` | 原材料退回供应商 |
| `ITEM_ISSUE_OUT` / `ITEM_ISSUE_IN` | 生产领用-出库 / 入库 |
| `OUTSOURCE_ISSUE_OUT` | 外协领用-出库 |
| `OUTSOURCE_RECPT_IN` | 外协入库-入库 |
| `ITEM_RT_ISSUE_OUT` / `ITEM_RT_ISSUE_IN` | 生产退料-出库 / 入库 |
| `TRANS_OUT` / `TRANS_IN` | 移库-移出 / 移入 |
| `ITEM_CONSUME` | 物料生产消耗 |
| `PRODUCT_PRODUCE` | 产品生产（产出） |
| `PRODUCT_RECPT_OUT` / `PRODUCT_RECPT_IN` | 产品入库-出库 / 入库 |
| `PRODUCT_SALSE` | 销售出库 |
| `PRODUCT_RT` | 销售退货 |

### 4.4 检验类型（`QC_TYPE_*`）

`IQC`（来料检验）/ `IPQC`（过程检验）/ `OQC`（出货检验）

## 五、核心机制：库存事务引擎

**这是整个 MES 最值得先读的一段代码。**

- 接口：`huaan-mes/.../wm/service/IStorageCoreService.java`
- 实现：`huaan-mes/.../wm/service/impl/StorageCoreServiceImpl.java`

### 5.1 设计思想

所有单据都不直接改库存，而是统一转成 `WmTransaction`（库存事务）交给引擎处理：

```java
// StorageCoreServiceImpl.processItemRecpt() 摘录
WmTransaction transaction = new WmTransaction();
transaction.setTransactionType(transactionType);   // 事务类型常量
BeanUtils.copyBeanProp(transaction, line);         // 从单据行拷贝物料/批次/库位/数量
transaction.setTransactionFlag(1);                 // ★ 方向：+1 加库存，-1 减库存
transaction.setTransactionDate(new Date());
wmTransactionService.processTransaction(transaction);
```

`transactionFlag` 是唯一的"加减"开关。引擎内部负责：写流水 → 定位或新建对应维度的库存记录 → 更新 `quantity_onhand`。

### 5.2 十二类库存事务对照表

| 引擎方法 | 来源单据 | 方向 | 事务类型 |
|---|---|---|---|
| `processItemRecpt` | 物料入库单 | **+1** | `ITEM_RECPT` |
| `processProductRecpt` | 产品入库单 | **+1** | `PRODUCT_RECPT_IN` |
| `processOutsourceRecpt` | 外协入库单 | **+1** | `OUTSOURCE_RECPT_IN` |
| `processRtSalse` | 销售退货单 | **+1** | `PRODUCT_RT` |
| `processRtIssue` | 生产退料单 | **+1** | `ITEM_RT_ISSUE_IN` |
| `processIssue` | 生产领料单 | **−1** | `ITEM_ISSUE_OUT` |
| `processOutsourceIssue` | 外协领料单 | **−1** | `OUTSOURCE_ISSUE_OUT` |
| `processProductSalse` | 销售出库单 | **−1** | `PRODUCT_SALSE` |
| `processRtVendor` | 供应商退货单 | **−1** | `ITEM_RTV` |
| `processItemConsume` | 物料消耗记录 | **−1** | `ITEM_CONSUME` |
| `processProductProduce` | 产品产出记录 | **+1** | `PRODUCT_PRODUCE` |
| `processTransfer` | 转移单 | **−1 / +1** | `TRANS_OUT` / `TRANS_IN` |

### 5.3 库存维度

`wm_material_stock`（库存现有量）的主键是 `material_stock_id`，业务上的唯一维度由这些列共同决定：

```
item_id + batch_code + warehouse_id + location_id + area_id + vendor_id + workorder_id
```

即**批次级 + 库位级 + 供应商级**的精细库存，不是简单的"物料总数量"。

## 六、四条主业务流程

### 流程一：基础数据准备（`md` + `qc` 配置）

```
计量单位 → 物料/产品 → 物料类型 → 产品BOM
车间 → 工作站（+ 设备资源 / 工装夹具资源 / 人力资源）
供应商 / 客户
工艺路线(proroute) → 工艺组成(routeprocess，定工序顺序 + 是否关键工序)
                        → 产品制程(routeproduct) → 产品制程物料BOM(routeproductbom，定每道工序耗料)
产品SOP / 产品SIP
检测项(qcindex) → 检测模板(qctemplate) → 模板-检测项(templateindex，定标准值与上下限)
                                        → 模板-产品(templateproduct)
```

> 这一步不做完，后面的生产流程跑不起来——**尤其"产品制程物料BOM"和"检测模板-产品"，缺了会直接报错**（见流程二、流程三）。

### 流程二：生产执行主流程 ★★（最重要）

```
① 建生产工单                     POST /mes/pro/workorder
   填产品、数量、需求日期          状态 = PREPARE
        ↓
② 工单BOM组成                    /mes/pro/workorderbom
        ↓
③ 排产：人工建生产任务            POST /mes/pro/protask
   选 工单 + 工序 + 工作站 + 排产数量 + 计划时间
   （工单的 quantityScheduled 累加；甘特图 GET /mes/pro/protask/listGanttTaskList 查看）
        ↓
④ 触控屏端作业
   选择工作站 → 拉任务列表 → 切换任务 → 开始/暂停/继续
        ↓
⑤ 生产报工（草稿）                POST /mes/pro/feedback
   填：报工数量 quantityFeedback
       合格数量 quantityQualified
       不良数量 quantityUnquanlified
       待检数量 quantityUncheck        ★ 关键字段
        ↓
⑥ 若 待检数量 > 0
   → 报工单出现在「待检池」(QcPendingInspectMapper，qc_type='PQC')
   → 质检员建 IPQC 单，按模板逐项检测，填缺陷数
   → 把 IPQC 单状态置为 FINISHED
   → 触发回写：pro_feedback.quantityUncheck = 0   （QcIpqcController:202~213）
        ↓
⑦ 执行报工 ★ 生产数与库存的联动点   PUT /mes/pro/feedback/{recordId}
   （ProFeedbackController:225，整体一个 @Transactional）
   ├─ 校验1：报工数量必须 > 0
   ├─ 校验2：任务已完成则不能报工
   ├─ 校验3：quantityUncheck > 0 直接报错「未完成检验，无法执行报工」
   ├─ 更新生产任务 ProTask：
   │     quantityProduced   += 本次报工数
   │     quantityQuanlify   += 合格数
   │     quantityUnquanlify += 不良数
   ├─ 若该工序是关键工序 checkKeyProcess()：
   │     ├─ 工单 quantityProduced += 本次报工数
   │     └─ 生成产品产出单 → processProductProduce()  → 库存 +1（入线边库）
   ├─ 按工序物料BOM生成消耗单：
   │     └─ processItemConsume() → 库存 −1（扣线边库，支持分批次领料）
   └─ 报工单状态置 FINISHED
        ↓
⑧ 任务/工单完成
```

**两个极易被忽略的设计要点**：

1. **只有关键工序才产出成品入库**。非关键工序报工只累加任务数量，不产生库存变动。
2. **质检是报工的前置条件**，通过 `quantityUncheck` 这个"待检数量"字段实现卡口，而不是通过库存冻结。

### 流程三：来料入库流程（IQC）

```
① 建物料入库单头                POST /mes/wm/itemrecpt
   填 供应商、仓库/库区/库位、入库日期
② 建入库单行                    POST /mes/wm/itemrecptline
   填 物料、入库数量 quantityRecived、批次 batchCode、库位
   选 是否来料检验 iqcCheck = Y/N     ★ 人工选择，默认 N
        ↓
③ 若 iqcCheck = 'Y' 且 iqc_id 为空
   → 该行出现在「待检池」(qc_type='IQC')
   → 质检员建 IQC 单（带 templateId）→ 按模板检测 → 保存
   → 回写 iqc_id/iqc_code 到入库单行 → 从待检池消失
        ↓
④ 执行入库                      PUT /mes/wm/itemrecpt/{recptId}
   storageCoreService.processItemRecpt(beans)  → 库存 +1
   单据状态置 FINISHED
```

> ⚠️ **重要提醒**：第④步**不校验 IQC 结果**。只要单据存在就能执行入库，检验没做、甚至判不合格也不阻塞。
> 详细缺口说明见第九节。

### 流程四：质量检验统一机制（待检池）

待检池不是一张表，而是一条**查询时实时计算的 SQL**（`huaan-mes/src/main/resources/mapper/qc/QcPendingInspectMapper.xml`），用 `UNION ALL` 汇总三种来源：

```sql
-- ① IQC：勾了要检验且未挂检验单的入库单行
FROM wm_item_recpt wi JOIN wm_item_recpt_line wil
WHERE wil.iqc_check = 'Y' AND wil.iqc_id IS NULL
UNION ALL
-- ② PQC：待检数量 > 0 的报工单
FROM pro_feedback pf WHERE pf.quantity_uncheck > 0
UNION ALL
-- ③ OQC：勾了要出货检验且未挂检验单的销售出库行
FROM wm_product_salse ps JOIN wm_product_salse_line psl
WHERE psl.oqc_check = 'Y' AND psl.oqc_id IS NULL
```

**检验结果的三条回写路径**：

| 检验类型 | 回写目标 | 回写代码位置 |
|---|---|---|
| IPQC | `pro_feedback`（合格数/不良数/待检清零） | `QcIpqcController.edit()` 第 202~213 行 |
| IQC | 入库单行的 `iqc_id` / `iqc_code` | 建单时写入，使该行退出待检池 |
| OQC | 出库单行的 `oqc_id` | 同上 |

> 注意：**IQC 和 OQC 只是从待检池移除，不驱动任何后续动作**（不冻结库存、不放行出货）。只有 IPQC 会回写并解锁报工。

### 流程五：出库与发货

```
生产领料：建领料单头/行 → 执行出库 → processIssue()         → 库存 −1
销售出货：建销售出库单头/行 → （可选 OQC）→ 执行出库
                              → processProductSalse()      → 库存 −1
生产退料：建退料单 → 执行 → processRtIssue()                → 库存 +1
供应商退货：建退货单 → 执行 → processRtVendor()              → 库存 −1
库间调拨：建转移单 → 执行 → processTransfer()               → 移出 −1 / 移入 +1
```
